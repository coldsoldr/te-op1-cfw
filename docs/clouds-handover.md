## 2. Done and verified

- **Upstream copied:** `ports/clouds/src/dsp/` (granular processor, players, correlator, phase vocoder, fx) and `src/resources.*`, copied from `mutableinstruments/clouds`.
- **Harness:** `harness/render.cc`, `scenarios.h` and `wav16.h`. It builds three ways: upstream (`-DREF`), the copy (`-DCOPY`) and the port (`-DPORT`).
- **21 scenarios** at upstream's 32 kHz, with music and a 400 Hz sine as inputs:
  - 11 looping delay (pitch −7/0/+5/+12, filters, diffuser, freeze, dry/wet sweep, pitch steps, position sweep, reverb + feedback, mono);
  - 9 granular (density, random, freeze, spread, knob sweeps, reverb + feedback, mono);
  - 1 mode switch.
- **The copy matches upstream bit for bit:** all 21 checksums are equal (`build/ref.txt` = `build/copy.txt`, `make copy-check`). Reference WAVs are in `out/ref/`. This is the baseline the fixed-point port is measured against.

## 3. Fixed-point design so far (`ports/clouds/src/core/`)

- **Formats** (`dsp_fixed.h`), as in Rings:
  - audio is Q27 in int32 (±16 headroom);
  - record buffers are int16, as upstream's 16-bit mode;
  - parameters are Q16 and coefficients Q31;
  - built on Rings' `fixed.h`, `ffloat.h` and `fixed_tables.h`.
- **Two rate profiles** (`config.h`, `OP1CLOUDS_SAMPLE_RATE`):
  - **32000:** upstream's constants, used only to compare sample for sample with the reference;
  - **44100:** the OP-1 build. Every time constant upstream gives in samples is scaled by 44100/32000, so the durations stay the same: record buffers, grain sizes, the pitch shifter's window, the diffuser delays, and the looper's crossfade and smoothing.
  - Not scaled:
    - the texture filters' normalised cutoffs (their knob range moves up ~5.5 semitones);
    - per-block smoothing;
    - Rings' reverb, whose delays already suit ~44 kHz.
- **Blocks:** upstream's 32-sample block. The OP-1's 64-sample effect call runs two of them.
- **Components written:**
  - `record_buffer.h`: upstream's circular int16 buffer with the 8-sample interpolation tail and the 256-sample freeze crossfade tail.
  - `svf_fixed.h`: stmlib's TPT SVF. FFloat coefficients per block (upstream's fast tan), g in Q28, h in Q31, states in Q27.
  - `diffuser_fixed.h`: 4 allpasses per side at 0.625, with an int32 Q27 buffer. Mono runs the left network only.
  - `pitch_shifter_fixed.h`: two crossfaded taps. The phase increment is computed once per block, so there's no division per sample.
  - `clouds_tables.*`: generated by `resources/gen_tables.py` from upstream's own float tables (grain sizes, grain window, crossfades, sine, pitch ratios), with one guard entry for interpolation.
- **Reused from Rings by path:** `reverb_fixed.*` (mono reverb), `reverb_bfin.S`, `cycles.h`, `compare.py`.
- **Grain cap:** 64 (upstream uses 32 stereo / 40 mono). The CPU budget will set the real number once Test 16 gives the free cycles.

## 5. How to resume

In WSL, from `ports/clouds`:

```
make copy-check   # upstream vs copy: must say bit-identical
make port         # fixed-point port at 32 kHz constants -> out/port/
make compare      # SNR vs out/ref ;  make spec  for band spectra
make port44       # OP-1 profile (44.1 kHz) -> out/port44/
make test         # kernels: Blackfin assembly = host C, wrap tests
make bench        # cycles per mode on bfin-elf-run (device ~1.6x)
make sim-fx       # the OP-1 entry points in the simulator
```

`port`, `test`, `bench` and `sim-fx` will fail until the files in §4 exist.

**Blocked on the user or the device:**
- **Test 16 results** (flash `op1_246_rings_fxprobe1.op1`, record the beeps, decode with `tools/decode_probe_beeps.py`). They give the effect call rate, whether it runs while off, phone's cost and the free CPU. That sets the grain count, the time-stretch search cap and whether to run below 44.1 kHz.
- **The Clouds screen SVG** (the user is drawing it; brief in `docs/clouds-screen-brief.md`).

**Still to find or build on our side:**
- the FX page's encoder and click hooks (for the controls in HANDOVER §3);
- the image restructure, so Rings and Clouds share one injected image: shared code moved to a common folder, and one top-level target.

## 6. Rules that apply

`docs/HANDOVER.md` §1 in full. In short:
- no `te-boot.ldr` in packages;
- every package passes `verify_bootloader.py` and a diff against stock;
- the user flashes, and only after being asked;
- no commits without asking.

For this code in particular:
- every assembly kernel gets a C reference and a bit-exact check;
- every ring buffer driven from assembly gets a wrap test with guard words;
- no non-constant `/` or `%` in audio loops;
- no static constructors (the image has no startup code).

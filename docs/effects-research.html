New effects for the OP-1: shortlist

Stereo reverb candidates plus saturation, distortion and a couple of other good finds. Research notes from 19 Oct 2026, checked against what the device measurements say the Blackfin BF524 can sustain.

Summary

  • Reverb, build first: Dattorro plate (low risk). Clouds' reverb is a cut-down Dattorro/Griesinger tank, and its assembly kernel and 22.05 kHz halfband path are already proven on the device. The full plate adds proper decorrelated stereo taps, tank modulation, pre-delay and a freeze. Estimated ~12–25 MHz on the device, compared with Clouds' 85.
  • Reverb, second mode: 8-line FDN "hall" with a real size control and a different character from the plate. It can share the plate's host and buffer, at a similar cost.
  • Saturation: one "DIRT" effect with four modes (Drive, Tape, Fold, Crush), on the MULTI pattern. It has no big buffers, so the cache misses that hurt Clouds don't apply. Estimated ~3–12 MHz.
  • Other good finds: a stereo chorus/ensemble (the stock OP-1 has none, and the code is already in the Rings and Plaits sources) and a frequency shifter / ring modulator from Warps.
  • Nothing from the plugin world can be dropped in as-is. The BF524 has no FPU, so float or double code (Airwindows, CloudSeed, Freeverb) gets rewritten in fixed point. In practice, "porting" means taking the topology and re-implementing it in the 16-bit MAC style of reverb_stereo_bfin.S.

Constraints these choices follow

CPU

About 300 MHz is free when idle. Heavy Rings leaves only ~40–75 MHz. Work that touches SDRAM buffers runs 2–4× the simulator (Tests 30–34: 16 KB caches, a miss costs 100–190 cycles). Keep the number of delay-line streams small and the per-call code small.

Stereo means the master slot

The synth and drum FX positions are mono (one object shared at 0xffb00600). Only the master position (0xffb00790) is stereo. Each design here also runs mono, at ~0.6× the cost, for the synth slot.

Code we already have

The 16-bit MAC reverb kernel with mirrored writes, the diffuser kernel, the 2:1 halfband decimator/interpolator (in assembly, bit-exact), the governor, Rings' soft-limit table, and the orange-click swap host pattern.

Licences

Mutable Instruments (MIT), Airwindows (MIT), el-visio's Dattorro C (MIT), fverb (BSD-2) and the Freeverb topology (public domain) are all fine to use. Plateau (Valley, GPL-3), MVerb (GPL) and zita-rev1 (GPL) are fine as reading material only, unless the firmware is GPL too.

Reverbs

1 · PLATE: Dattorro figure-of-eight

Recommended first

This is the classic 1997 JAES plate ("Effect Design Part 1"). The input goes through a band-limiting filter and four input allpass diffusers, then into a two-half tank that cross-feeds in a figure of eight. Each half has a modulated allpass, a delay, a damping low-pass, a decay allpass and a second delay. Seven output taps per side, read from different points in both halves, give wide, decorrelated stereo from the mono sum. That's the main audible step up from Clouds' 2-tap version.

2 · HALL: 8-line feedback delay network

Second mode

This is Jot's FDN, laid out as in Signalsmith's "Let's write a reverb": a few short diffuser steps (each with a channel shuffle and a Hadamard mix) for the early density, then eight delays with a Householder feedback matrix. Householder costs only N adds, one multiply and N subtracts, with no N² multiply. Each line has a one-pole damping filter. Even-numbered lines feed L and odd-numbered lines feed R. Unlike the plate, the line lengths scale cleanly, so SIZE goes from a small room to a big hall. The character is smoother and less "ringy" than a plate.

L/R → pre-delay→3× diffuser step (shuffle + Hadamard)→8 delays→damp ×8→Householder↺even → L, odd → R

Saturation and distortion: "DIRT", one host with four modes

One effect, with the mode on the blue click, the same pattern as MULTI and Clouds. None of the modes uses a large buffer, so they mostly avoid the cache misses that hurt the reverbs. The real problem with distortion here is aliasing. The plan is to run each shaper at 88.2 kHz between the existing halfband interpolator and decimator (2× oversampling, already in assembly). Where that isn't enough, first-order ADAA (antiderivative antialiasing) goes on top.

DRIVE

Build first

Soft clip with pre/post tilt EQ and a bias for even harmonics. The core is Plaits' Overdrive (MIT, already in mutableinstruments/plaits/dsp/fx/overdrive.h), with its gain staging that keeps the level roughly constant. Use a table soft clip like Rings' limiter, not float maths.

TAPE

Good fit

Gentle saturation, a head-bump low shelf, high-frequency loss, wow and flutter, and optional hiss. Beads' WowAndFlutter (MIT, in the repo) handles the motion. The saturation follows Airwindows ToTape's approach (MIT), rewritten in fixed point. It fits the OP-1's tape metaphor.

FOLD

Watch aliasing

A wavefolder: either Warps' ALGORITHM_FOLD (MIT, in the repo) or a Lockhart/Serge folder model with first-order ADAA. It's harsh and synthy, and best on the synth slot. It needs 2× oversampling plus ADAA, since folding multiplies aliasing.

CRUSH

Trivial

Bit-depth and sample-rate reduction. Plaits' SampleRateReducer (MIT, in the repo) does an optionally anti-aliased sample-and-hold. Requantising a 16-bit signal costs almost nothing. Jitter makes it sound like a dying sampler.

TAPE in depth: sources and chain

Reference + cheap code

Two sources, used together: Chowdhury's paper is the physical reference for the curves and parameter ranges, and Airwindows gives code light enough to rewrite in fixed point.

SourceLicenceWhat we takeWhat we leave
Chowdhury, "Real-Time Physical Modelling for Analog Tape Machines", DAFx-19 (paper, ChowTapeModel) Paper: CC-BY 3.0. Plugin code: GPLv3 (read only). The play-head loss formulas (spacing loss e−kd, thickness loss, gap sinc; k = 2πf/v), which give the HF roll-off and head bump at each tape speed. Also the measured TC-260 constants and the way it measures wow and flutter from a real machine. The hysteresis solver. It runs Jiles-Atherton with an RK4 step on every sample at 16× oversampling, with a coth function at each step: far beyond budget with no FPU.
Airwindows ToTape9 / IronOxide5 (airwindows/airwindows, plugins/LinuxVST/src/; ToTape9 page) MIT The saturation core: ToTape9 clamps to ±2.306 and applies an odd polynomial approximating sin(); IronOxide clamps to π/2 and takes sin(). Both become a lookup table, like Rings' soft limiter. Also ToTape9's "tiny hysteresis" (a small clamped integrator with feedback) and its head bump (two biquads per channel). Two chains of averaging filters (up to ~124 additions per channel per sample; 1–2 biquads do the same job as a steep low-pass), the "Dubly" compander (log() calls), the look-ahead clipper and the dither.
Beads WowAndFlutter (mutableinstruments/beads/dsp/fx/wow_and_flutter.h) MIT, in the repo The whole stage: a small modulated delay with a randomly drifting rate. Nothing

Other good finds

ENSEMBLE: chorus / string ensemble

Cheap, stereo

The stock OP-1 has no chorus. Rings (fx/chorus.h, fx/ensemble.h) and Plaits (fx/ensemble.h) already contain MIT, FxEngine-based versions that share the reverb's coding style. The ensemble mode uses three phase-spread taps per side for the Solina sound.

Memory~2k samples

SHIFT: frequency shifter / ring mod

Medium effort

Warps' quadrature transform (MIT, warps/dsp/quadrature_transform.h) gives a Bode-style frequency shifter. Shifting L up and R down gives instant width, and adding feedback gives barber-pole sweeps. Warps' diode ring modulator model is in the same module.

Open decisions for you

  1. Hosts: which stock effects do the new ones swap with on the orange click? A natural fit would be spring ↔ PLATE/HALL and punch or nitro ↔ DIRT. Phone is already Clouds, and filter is kept free for op1repacker.
  2. Reverb order: plate first, then hall as a mode (proposed), or hall only?
  3. DIRT scope for v1: all four modes, or Drive + Crush first (the cheapest to prove the host)?
  4. Manual note: as with Rings + Clouds, any of these next to Rings at "all" eats into the same budget. Should the reverb get the governor treatment (dropping to the 4-line FDN or skipping modulation under load)?
